# 14. 독립성 검사 · 문서 · 납품

```
명령어/14 단계. 계약서 7조 납품물(앱 소스·빌드, 서버 소스·DB 구조, 웹·관리자, 설치·배포 안내서)을 완성하고, 대표님이 자정사주 없이 혼자 운영할 수 있는지 검증한다.
1. npm run check:independence 통과 + reference/ 폴더는 납품 저장소에서 제외(.gitignore 가 아니라 git 이력에도 없게 — 처음부터 커밋하지 않았는지 git log --all -- reference 로 확인, 있으면 보고).
1-2. 납품용 저장소는 내부 작업 자료를 뺀 깨끗한 사본으로 만든다: 명령어/, 진행상황.md, 내할일.md, 결정필요.md, docs/reference분석.md, docs/독립양도구조.md 의 금지 문자열 목록, docs/시안/ 작업본, docs/sample-readings(원가 정보) 제외. CLAUDE.md 는 자정사주 언급을 지운 운영용 버전으로 교체. 이 사본에서는 check:independence 를 제외 목록 없이(전 파일 대상) 돌려 통과해야 한다. 스크립트 npm run export:delivery → ../naman-unse-delivery 폴더 생성(git 이력은 새로 시작, 스쿼시).
2. 자정사주 문구 겹침 검사 통과, 비밀·키 스캔(gitleaks 류 간이 스크립트: sk-ant-, AIza, -----BEGIN, xkeysib-, .jks).
3. README.md(설치·배포 안내서, 한국어, 40~60대 대표님도 따라 할 수 있게 화면 순서대로): 준비물 → 처음부터 설치하기(Windows 기준) → 환경변수 표(이름·설명·어디서 받는지 링크) → Railway 배포 → 도메인 연결 → Play Console 상품 등록 → Firebase·AdMob 연결 → 관리자 계정 만들기 → 가격·문구 바꾸는 법(brand.config.json, content/) → 자주 묻는 문제.
4. docs/HANDOVER.md: docs/독립양도구조.md 의 양도 체크리스트를 실제 값·링크·캡처 자리로 채우기. 대표님 계정으로 옮길 항목 표(항목 / 현재 소유 / 옮기는 방법 / 완료 체크).
5. 빈 폴더 검증: 저장소를 새 폴더에 git clone → .env.example 복사 → npm ci → db:migrate → db:seed → admin:create → npm run build → 서버·웹 실행 → Playwright 전체 시나리오 통과. 결과를 docs/설치검증.md 에.
6. 버전 태그 v1.0.0, CHANGELOG.md.
7. 최종 보고: 납품물 4종 경로, 남은 대표님 작업(계정·키·가격), 알려진 제한사항.
```
