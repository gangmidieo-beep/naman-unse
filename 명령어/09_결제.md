# 09. 결제 — Google Play 구독·단건(서버 검증) + 웹 PG

```
명령어/09 단계. 계약서 2조 "Google Play 월 구독(서버 대조 검증, 구매복원·자동갱신·해지·환불 처리), 단건 인앱결제(정통사주·궁합·신년운세)" + "웹 전용 PG 결제". 대표님 계정이 아직 없으므로 전부 인터페이스 + mock + 테스트로 완성하고, 키만 넣으면 동작하게 만든다. 막히는 계정 작업은 내할일.md(링크 포함)에.

[1. Google Play 서버 검증 — server/src/services/google-play.ts]
- googleapis androidpublisher v3, 서비스 계정 JSON 은 환경변수 base64.
- 단건: POST /billing/google/verify-product {productId, purchaseToken} → purchases.products.get → purchaseState=0 확인 → acknowledge(3일 내 필수) → orders paid + entitlements(kind=product) → 풀이 생성 큐.
- 구독: POST /billing/google/verify-subscription {purchaseToken} → purchases.subscriptionsv2.get → subscriptionState 에 따라 entitlements 갱신(ACTIVE/IN_GRACE_PERIOD=이용 가능, ON_HOLD/PAUSED=중지, CANCELED=만료일까지 이용 후 종료, EXPIRED=종료) → acknowledge.
- 중복 방지: purchaseToken 유니크 인덱스, linkedPurchaseToken 처리(업그레이드·재구독 시 이전 토큰 무효화).
- RTDN: POST /billing/google/rtdn (Pub/Sub push, JWT audience 검증) → notificationType 별 재조회 후 반영(RENEWED, CANCELED, EXPIRED, REVOKED, ON_HOLD, IN_GRACE_PERIOD, RECOVERED, RESTARTED, PAUSED). 단건 환불은 voidedpurchases.list 를 하루 1회 cron 으로 조회해 권한 회수.
- 구매 복원: POST /billing/google/restore {purchases[]} → 전부 재검증.
- 모든 상태 전이를 단위 테스트로(가짜 응답 JSON 픽스처). 테스트 이름에 한국어 시나리오: "해지하면 만료일까지는 프리미엄 유지", "환불되면 즉시 회수", "결제 실패 유예기간엔 유지" 등.

[2. 앱 쪽 — web/src/platform/google-play.ts (10 단계에서 네이티브 연결)]
- cordova-plugin-purchase v13(CdvPurchase) 래퍼: 상품 등록 → 구매 → 영수증 서버 검증 → finish. 앱 시작 시 restore + 서버 권한 재조회.
- Play 정책: 앱 안에서 디지털 콘텐츠는 Google Play 결제만. 앱에서 웹 PG 결제 링크·안내 절대 노출 금지(플랫폼 분기 테스트 작성).

[3. 웹 PG — server/src/services/pg/]
- PaymentProvider 인터페이스: createPayment(order) → {redirectUrl|widgetParams}, confirm(params), handleWebhook(req), refund(order).
- 구현: mock(완성) + toss(토스페이먼츠 결제위젯 v2 기준 — 결정필요 D3 가 토스로 확정되면 키만 넣으면 되게, 공식 문서 https://docs.tosspayments.com 참고해 최신 방식으로). 다른 PG 로 결정되면 같은 인터페이스로 추가.
- 금액 위변조 방지: 서버 주문 금액과 승인 금액 대조. 웹훅 서명 검증. 멱등키.
- 웹 구독: PG 정기결제(빌링키)는 PG 확정 후 — 1차는 웹 "프리미엄 30일 이용권" 단건 결제로 대체 가능하게 옵션화(brand.config webPremiumMode: "pass30"|"billing"), 결정필요.md 에 D9 로 추가.
- 결제 완료 → 결과 페이지 이동(returnUrl 은 PUBLIC_WEB_ORIGIN 기준, 하드코딩 금지 — 과거 자정사주에서 도메인 하드코딩 때문에 결제완료 이벤트가 안 잡힌 사고가 있었다. 테스트로 막아).

[4. 권한 통합]
- entitlement 서비스 하나로: isPremium(user), canRead(user, productId), discountFor(user, productId). 화면은 이것만 본다.
- 앱·웹 계정 연결 시 권한 합치기(같은 사용자 로그인 연결 시).

[5. 마무리]
- 테스트 전부 통과, check:independence 통과. 커밋. 내할일.md 에 추가: Play Console 상품 등록 방법(구독 id·기본 요금제·단건 id), 서비스 계정 연결, RTDN Pub/Sub 주제 생성 — 각 링크 포함(https://play.google.com/console , https://console.cloud.google.com/cloudpubsub). 3줄 보고 후 명령어/10 으로 계속.
```
