# 11. 유료 풀이 AI 파이프라인 (정통사주·궁합·신년운세)

```
명령어/11 단계. reference 의 풀이 생성 파이프라인 "구조"(프롬프트 → 장별 JSON → 검증 → 저장 → 렌더)만 참고하고, 프롬프트·문장은 새로 쓴다. API 키는 이 프로젝트 전용 개발 키(.env)만, 없으면 mock 으로 끝까지 구현.

[1. 구조 — server/src/services/reading/]
- 입력: 엔진 결과(원국·오행·십신·12운성·대운·세운) + 상품 + (궁합이면 2인) + 고민 칩(05 단계 상담에서 고른 것).
- 상품별 장 구성(content/data/reading-outline/*.json 으로 관리):
  - 정통사주(천궁도령): 타고난 그릇 / 성격과 강점 / 재물 흐름 / 직업·일 / 사람 복·가족 / 건강 습관 / 대운 10년 흐름 / 앞으로 3년 / 도령의 당부 (고민 칩이 재물이면 재물 장 2배 분량)
  - 궁합(월하선녀): 두 사람의 기운 / 끌림 / 부딪히는 지점 / 대화법 / 돈·생활 궁합 / 앞으로의 인연 흐름 / 선녀의 당부
  - 신년운세(천궁도령): 한 해 총평 / 월별 12개 / 재물·직장·애정·건강 요약 / 조심할 달·좋은 달
- 호출: 장 묶음 2~3번에 나눠 호출(긴 응답 안정성), JSON 스키마 강제, 실패 시 해당 묶음만 재시도(최대 2회). 모델명은 ANTHROPIC_MODEL 환경변수(기본값 비워두고 README 에 권장값).
- 비용 기록: tokens_in/out, cost_krw 를 readings 에 저장 → 관리자 화면에 건당 원가 표시.
- 품질 검사(자동): 이름·생년월일 정확, 원국 한자가 엔진값과 일치, 장 누락 없음, 금지어(사망·이혼 확정·파산·질병 단정·투자 권유), 캐릭터 어미 일관, 자정사주 문구 겹침 검사(check-copy-overlap).
- 비동기: 결제 완료 → 큐(DB 폴링 워커, 동시 3개) → 화면은 3초마다 상태 조회. 생성 실패 시 관리자 needsAttention + 사용자에겐 "잠시 후 다시 확인" + 자동 재시도.

[2. 프롬프트 작성 원칙]
- 40~60대 독자, 쉬운 말, 한 문단 3~5문장, 근거(어느 글자·어느 기운 때문에)를 한 줄씩 붙여 "맞는 말" 느낌.
- 단정·공포 금지, 희망적 마무리, 구체적 행동 조언(요일·색·방향·사람 유형).
- 도령=하오체, 선녀=해요체. 예시 문장은 새로 작성.

[3. 샘플·비용 확인 — 여기서 한 번 멈춤]
- 실제 API 로 샘플을 돌리기 전에 멈추고 보고: "샘플 3건(정통사주·궁합·신년운세) 예상 토큰·예상 비용(원)". 사람이 "진행" 이라고 하면 실행.
- 결과를 docs/sample-readings/ 에 저장하고, 자동 품질 검사 결과표 첨부.

[4. 마무리]
- mock 모드에서도 전체 흐름 테스트 통과. 커밋, 진행상황.md, 3줄 보고.
```
