# 08. 서버·DB·관리자

```
명령어/08 단계. server/ 를 만든다. reference 의 관리자·이벤트 추적·결제 콜백 "구조"는 참고하되 코드는 이 프로젝트 이름·스키마로 새로 쓴다. 자정사주 URL·키·도메인 금지. 묻지 말고 끝까지.

[1. 기본]
- Fastify + TypeScript + Drizzle ORM + PostgreSQL. 로컬은 docker compose(postgres:16) — docker 가 없으면 pglite 로 대체해 테스트.
- 구조: src/routes, src/services, src/db/schema.ts, drizzle/ 마이그레이션, src/plugins(auth, cors, rate-limit, error).
- CORS 는 PUBLIC_WEB_ORIGIN + capacitor://localhost + http://localhost 만.
- 헬스체크 GET /health. Dockerfile(멀티스테이지, node:22-slim).

[2. DB 스키마 (drizzle/0001_init.sql 로 납품물 "DB 구조" 겸함)]
users(id, device_id, google_sub?, kakao_id?, email?, created_at, last_seen_at, font_scale, push_time, push_token?, platform)
profiles(id, user_id, name, gender, birth_date, calendar, leap_month, birth_time?, time_unknown, is_main, created_at)
products(id, type[single|subscription], title, price, google_product_id, active, sort, meta jsonb)
orders(id, user_id, profile_id, product_id, amount, channel[google|pg|free], status[pending|paid|failed|refunded|cancelled], provider_ref, created_at, paid_at)
entitlements(id, user_id, kind[premium|product], product_id?, source_order_id, starts_at, expires_at?, status[active|grace|on_hold|expired|revoked])
readings(id, order_id, profile_id, product_id, status[queued|generating|done|failed], content jsonb, model, tokens_in, tokens_out, cost_krw, created_at, done_at)
events(id, user_id?, session_id, name, props jsonb, utm_source, utm_medium, utm_campaign, referrer, install_referrer, platform, created_at) — 인덱스(name, created_at)
push_campaigns(id, title, body, deep_link, target[all|free|premium], scheduled_at, status, sent_count, created_by)
exit_popup(id, mode[admob|image], image_url?, link_url?, ratio, active, updated_at)
admins(id, email, password_hash, created_at)
daily_stats(date, signups, dau, orders, revenue, pay_open, pay_success) — 매일 00:10 집계 cron

[3. API]
- 인증: POST /auth/guest(device_id → JWT), POST /auth/link/google, /auth/link/kakao(자리만, 키 오면 구현). JWT 30일.
- 프로필 CRUD /profiles. 오늘의 운세는 클라이언트 계산(오프라인 가능)이 기본, 서버 GET /fortune/today 도 같은 packages/content 로 제공(웹 SEO·공유 링크용).
- 상품 GET /products (brand.config 와 동기화 스크립트 db:seed).
- 주문 POST /orders, GET /orders/:id, 풀이 GET /readings/:id (본인 것만).
- 권한 GET /me/entitlements — 서버가 유일한 진실. 클라이언트는 캐시만.
- 이벤트 POST /events (배치, 최대 50개, rate limit). 웹은 utm 파라미터·referrer 첫 방문 시 저장, 앱은 install referrer(10 단계).
- 공유 링크 GET /s/:code → 결과 요약 OG 이미지 + 앱/웹 열기.

[4. 관리자 /admin (web 안의 별도 라우트, 서버 /admin/api/*)]
- 로그인(이메일+비밀번호, bcrypt, 5회 실패 잠금). npm run admin:create 스크립트.
- 대시보드: 오늘/어제/7일/30일 카드(가입·방문(DAU)·결제 건수·매출) + 일별 꺾은선 + 표(엑셀 다운로드 CSV).
- 유입 경로: utm_source·referrer·install_referrer 별 가입·결제 전환 표.
- 결제 퍼널: 상품 보기 → 결제창 열기 → 결제 시작 → 성공/취소/실패, 단계별 이탈률, 상품별.
- 주문·구독 목록(검색·필터·환불 표시), 풀이 재생성 버튼(AI 재호출 없이 저장본 재열람 / 필요 시 재생성).
- 푸시: 문구 작성(제목·본문·딥링크·대상) → 미리보기 → 즉시/예약 발송 → 발송 결과. 예약은 서버 cron(1분 주기) — 10 단계에서 FCM 연결 전까지 MOCK 발송 로그.
- 종료 팝업 설정: AdMob / 이미지+링크 선택, 이미지 업로드(서버 로컬 볼륨 또는 S3 호환 — 기본은 Railway 볼륨), 노출 비율, 켜기/끄기.
- 상품·가격 수정(Play Console 가격과 다르면 경고 문구).
- 매일 오전 7시 "오늘의 운세" 자동 푸시 기본 캠페인(사용자별 push_time 존중).

[5. 테스트·마무리]
- API 통합 테스트(vitest + supertest 류): 게스트 가입→프로필→주문(mock 결제)→권한 확인→풀이 조회, 관리자 로그인·통계.
- web 을 서버 API 에 연결(MOCK_MODE=false 로 켜도 로컬에서 동작).
- 커밋, 진행상황.md 갱신, 3줄 보고 후 명령어/09 로 계속.
```
