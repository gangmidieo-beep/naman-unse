# 나만의 운세 — 독립 양도 구조 (v1, 2026-09-29)

## 원칙
자정사주 **엔진과 틀(화면 뼈대·관리자·결제 처리 패턴)은 가져다 써도 된다.** 단, 완성물은 대표님에게 통째로 넘겼을 때 **자정사주 서버·계정·키·도메인이 하나도 없어도 혼자 돌아가야 한다.**

| 구분 | 허용 | 금지 |
|---|---|---|
| 만세력 엔진 코드 | ✅ 복사해서 `packages/engine` 에 넣기 (계약서 11조 4항: 을의 범용 모듈) | ❌ 자정사주 API 서버를 호출해서 계산 |
| 화면·관리자·결제 로직 틀 | ✅ 구조·로직 참고해서 새로 옮기기 | ❌ 자정사주 브랜드명·문구·이미지 잔존 |
| 풀이 문구 | ❌ 문장 재사용 금지 → 새로 작성 | |
| 키·계정 | ✅ 개발 중엔 `mock` 또는 **이 프로젝트 전용 개발 키** | ❌ 자정사주·비밀신당 운영 키, PayApp 계정, 메타 픽셀 ID, Railway 서비스 ID |
| DB | ✅ 이 프로젝트 전용 Postgres | ❌ 자정사주 DB 공유 |

## 기술 선택 (결정 완료 — 바꾸지 않음)

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | **Capacitor 7 + Android** (WebView 하이브리드) | 웹과 화면 코드 100% 공유, 요구사항의 "앱과 같은 화면·브랜드" 충족 |
| 화면 | Vite + React + TS | Capacitor 호환이 가장 단순, 정적 빌드 |
| 서버 | Node 22 + Fastify + Drizzle + PostgreSQL | 사용자 기존 Railway·Node 환경과 동일 |
| 구글 결제 | `cordova-plugin-purchase` v13 (Capacitor 호환) + 서버 검증 `googleapis` androidpublisher v3 + RTDN(Pub/Sub 푸시) | 구독 갱신·해지·환불 서버 대조 |
| 광고 | `@capacitor-community/admob` | 배너·전면(종료 팝업) |
| 푸시 | `@capacitor/push-notifications` + `firebase-admin` (FCM) + 서버 예약 발송(cron) | 관리자 예약 발송 |
| 공유 | `@capacitor/share` + 결과 이미지 `html-to-image` | |
| 웹 PG | `PaymentProvider` 인터페이스 + `mock` 구현 먼저 → 대표님 PG 확정 후 구현체 추가 | PG 미정(결정필요) |
| 배포 | Docker → Railway (대표님 계정) | 양도 시 계정만 대표님 것으로 |

## 양도(납품) 체크리스트 — docs/HANDOVER.md 로 만들 것
1. GitHub: 대표님 계정에 비공개 저장소 생성 → 전체 이력 push (또는 저장소 Transfer)
2. Railway: 대표님 계정에 프로젝트 생성 → server·web 서비스 + Postgres 추가 → 환경변수 입력 → 도메인 연결
3. DB: `npm run db:migrate` + 관리자 계정 생성 `npm run admin:create`
4. Firebase: 대표님 계정 프로젝트 → `google-services.json`(git 제외) → FCM 서비스 계정
5. Google Play: 대표님 조직 계정 → 앱 생성 → **Play 앱 서명** 사용, 업로드 키는 대표님 명의로 생성해 대표님이 보관(을은 사본 보관 안 함) → 구독·단건 상품 ID 등록(`brand.config.json` 과 동일) → 서비스 계정 권한 → RTDN 주제 연결
6. AdMob: 대표님 계정 앱·광고 단위 ID
7. PG: 대표님 사업자 가맹 → 키 입력 → 실결제 1건 확인 → 환불 확인
8. `npm run check:independence` 통과 화면 캡처 첨부
9. README 의 "처음부터 설치하기" 대로 **빈 PC 에서** 한 번 설치·실행 검증
10. 을 쪽 개발 키·테스트 계정 삭제, 멤버 초대 해제 요청
